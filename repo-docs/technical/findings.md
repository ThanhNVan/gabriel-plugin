# Findings

Known gaps, and places where the docs and the code disagree. Checked in the code on 2026-11-15. Fixed that day: the undeclared `dompurify` package, the session gate with 2 or more pins, and pin commands in `brain.js context`. Fixed 2026-11-16: a prompt sent during a private real-data test no longer aborts it. Test session ids start with `gtest-`, and the snapshot guard in `private/tests/lib.js` allows a live session's history appends and its own `seen/` files.

## Open gaps

1. **The chain setting rests on 100 questions (50 tune, 50 check).** The `chain` defaults ([R34](../business/02-business-rules.md#r34-two-links-away-code-names)) were set on 18 questions and are not re-tested on the 100. The check half went from 21/50 to 27/50 after the stem and name change. The name lookup for `On<stem>` handlers fixed CH-15 (checked 2026-11-16). CH-14 still fails: its code hits have the stem `PurchaseOrderLine`, but the handler is `OnUpdateMDProbabilityRequested`, so no stem matches.
2. **The map often does not show the asked function in Makillez.** Exact eval (2026-11-16, 100 cases): strict check half 15/50 to 23/50 after `pairHandlers()`. The gabriel-dev score moves with the doc text, not only the code: it was 9/15 before the 2026-11-15 doc edits, and is 7/15 now. The question names only one word of the code name (`CompanyRepository` from "company"), and `addNamedCode()` needs two matching words. A one-word rule in `addNamedCode()` was tried and dropped: no change on the tune half at 9 settings. Earlier tries dropped (no eval change): stem siblings by one strong link, and methods taking a weak type's slot in `pickResults()`. Next idea, tested offline (2026-11-16): a meaning index over code names, with the meaning model tuned on template questions made from code names and folders. The asked code was in its top 8 for 84/100 exact and 86/100 chain cases (today: 52 and 39). Not built yet. Details: `private/plans/2026-11-16-code-meaning-spike-plan.md`. A small reranker was tried and stopped (2026-11-16, branch `feature/code-rerank`, easy cases removed). A 50-item candidate pool (`search({ pool: true })`) holds the asked code for 317/396 code cases, against 198/396 in the 6 shown slots. A cross-encoder (MiniLM, trained on template questions from class names) then picked the 6 slots. Check half: 98/198 before, 82/198 after. AIPO fell from 13 to 4, because most of its asked code is functions and methods, and the training had no method names. The pool and the method-name meaning numbers stay (`codePool()`, opt-in). The reranker is now wired in (`rerankMap()` in `src/rerank.js`, called by `brain.js`), and runs only when `rerankModel` is set. A second try (method names, longer scenario-style template questions, negatives mined by meaning) was worse: check half 98/198 to 56/198. A reranker trained only on made-up questions does not transfer to the real ones. A third try (2026-11-17) trained on 1,483 real, checked train-only questions (Makillez 605, ESG 598, AIPO 63, gabriel-dev 217; `src/tune/real-pairs.js`, negatives from the pool). It was the worst: check half 98/198 to 41/198, every project but gabriel-dev down. Training and use build the same text (`codeText(label, file)`), so this is not a format mismatch. A name-and-path text alone does not carry what the current order uses (graph links, doc hits). Details: `private/plans/2026-11-16-code-rerank-plan.md`.
3. **A very slow disk can leave lines unchecked.** `exactLines()` stops at 5 s (`BUDGET_MS` in `src/repo.js`). Items not reached keep the graph's line, with no mark. The old 450 ms limit was hit once on a cold run (458 ms). Fix: none needed unless it shows again.
4. **gabriel-dev questions route to gabriel when nothing is pinned.** Both sets use the same code graph. In the private baseline (2026-11-15, meaning model on), only about 1 in 4 gabriel-dev questions picks gabriel-dev, though its own map holds the right doc for about 95%. Fix: not planned yet. Try a `cwdHints` or prior change, then compare with `node private/tests/baseline.js --compare`.
5. **A Python cache file is tracked in git.** `src/tune/__pycache__/train.cpython-314.pyc` is in git. The `.gitignore` file has the `__pycache__/` rule since 2026-11-23. Fix: untrack the file with `git rm -r --cached src/tune/__pycache__`.
6. **Two doc sets share the alias `gabriel`.** In `private/projects.json`, the sets `gabriel-dev` and `gabriel` both list the alias `gabriel`. A prompt that says "gabriel" can route to either set. Fix: not decided.
8. **A map build can empty the map of a prompt sent at the same time.** After an `embedModel` change, the first prompts start a background rebuild of each doc set. A search that meets the write lock fails open with no map (`search: database is locked` in `debug.log`). Seen 2026-11-19: 10 of 30 test questions got no map, and two `build-mk tech` processes ran at once. Fix: not decided. Retry the read once, or rebuild every set right after the keep in `tune.js`.
7. **A `nomap` case in `eval/eval-rules.js` is out of date.** The case "what is eval-rules.js about?" expects no map. It was written before the `gabriel-dev` doc set existed. The map now shows `gabriel-dev` for it, so the eval exits 1. When every rule is `inContext`, the eval skips the rule cases and scores only the 3 map cases (2/3 on 2026-11-18). Fix: not decided. Drop the case, or change its prompt to one that no doc set covers.
